Current repo structure and purpose
- provider.tf configures the AzureRM provider and backend block.
- main.tf is the root module that calls the child module in Terraform/modules/rg.
- variables.tf defines the input variables for the root module.
- terraform.tfvars provides environment values such as the Azure region.
- Terraform/modules/rg/main.tf creates the Azure resource group.
- Terraform/modules/rg/variables.tf defines the child module inputs.
- terraform.tfstate stores Terraform state for the current workspace.

Current Terraform design in this repo
- The root module selects one resource group name based on the active Terraform workspace.
- main.tf uses `var.resource_group_names[terraform.workspace]`.
- variables.tf currently defines resource_group_names as a map(string):
  test = "test-myrg"
  dev  = "dev-myrg"
- terraform.tfvars currently sets `resource_group_location = "eastus"`.
- Result: the current design creates one resource group per workspace, not both at the same time.

Example of current behavior
- If the active workspace is `test`, Terraform targets `test-myrg`.
- If the active workspace is `dev`, Terraform targets `dev-myrg`.
- To create both `test-myrg` and `dev-myrg` in a single apply, the design must be changed to `list(string)` plus `for_each`.

Terraform concepts covered during this work
- Provider: AzureRM provider for Azure resources.
- Backend: remote or local state configuration through the backend block.
- State: terraform.tfstate tracks managed infrastructure.
- Root module: entry point for Terraform execution.
- Child module: reusable module under Terraform/modules/rg.
- Variables: definitions in variables.tf and values in terraform.tfvars.
- Workspaces: using terraform.workspace to switch environment-specific values.
- Import: bringing manually created Azure resources into Terraform state.
- Generated config: using terraform plan -generate-config-out to generate Terraform code.
- Drift detection: terraform plan compares configuration with real Azure resources.
- Validation and formatting: terraform validate and terraform fmt.

Terraform command summary
- terraform init: initialize the working directory and download providers and modules.
- terraform validate: check whether the configuration is valid.
- terraform fmt: format Terraform files.
- terraform plan: preview changes.
- terraform apply: apply changes.
- terraform destroy: destroy managed resources.
- terraform import: attach an existing resource to state.
- terraform show: inspect state or a plan file.
- terraform output: display output values.
- terraform state list: list resources in state.
- terraform workspace list: show all workspaces.
- terraform workspace select <name>: switch workspace.

Import workflows discussed
Option 1: terraform import
- Imports an existing Azure resource into Terraform state.
- It does not fully generate Terraform configuration by itself.

Example:
terraform import azurerm_virtual_network.vnet '/subscriptions/085e0457-c5a2-4c4f-89db-0f8d8b4ede3c/resourceGroups/myrg/providers/Microsoft.Network/virtualNetworks/myvnet'

Option 2: aztfy
- Generates Terraform configuration for existing Azure resources.
- Example:
  aztfy resource-group myrg
- In the interactive workflow, entering `w` writes the generated files into the current directory.

Option 3: import block plus generated config
- Add an import block to main.tf:

import {
  id = "/subscriptions/085e0457-c5a2-4c4f-89db-0f8d8b4ede3c/resourceGroups/myrg/providers/Microsoft.Network/virtualNetworks/myvnet"
  to = azurerm_virtual_network.vnet
}

- Then run:
  terraform init
  terraform plan -generate-config-out="vnet.tf"

6. Review the plan output.
7. Apply the saved plan
   terraform apply tfplan

Common mistakes to avoid
- Running terraform plan -generate-config-out against a file that already exists.
- Expecting terraform import to generate full configuration automatically.
- Mixing list(string) and string types across root and child module inputs.
- Expecting a workspace-based map lookup to create multiple resource groups in one run.
- Typing tarraform or teraform instead of terraform.
